# Native setup diagnostics (C9)

This diagnostic candidate preserves every C8 setup qualification, dirty assignment, ticket invalidation, stopped guard and synchronous prime. It does not repair or qualify offline export or audio.

Each bound native component retains the first 32 reserved Bridge setup callbacks, exposing each only after completion. The 24-byte SDK ProcessSetup POD and original result are copied directly from the existing callback arguments. Numeric metadata includes existing thread flags and atomic cache epoch, dirty and qualified observations immediately before the existing body and after it returns. No additional native call, SDK call, clock, source/PCM read, file access, allocation, or string construction occurs in observation. A successful synchronous prime can change after-values; these are observations, not a proof that setup alone caused every epoch change.

A separate capacity-saturating atomic reservation assigns each immutable slot once. Total callback count separately saturates at UINT64_MAX and never addresses slots. Each owning callback publishes ready with release only on completion, including early returns; main status reads POD only after acquire-ready. Pending slots are omitted. Overflow events increment total count but cannot overwrite the first 32 preimages. History is deliberately not a ring.

Per-insert JSON exposes native_setup_diagnostic_count, native_setup_history_capacity (32), native_setup_history_overflow, native_setup_history_count_saturated, native_setup_history_completed_only, native_setup_history_ready_mask, and native_setup_history. Each event includes sequence, process_mode, symbolic_sample_size, max_samples_per_block, sample_rate, sample_rate_finite, original_result, main_thread, inside_native_process, cache_epoch_before/after, dirty_before/after and setup_qualified_before/after. A nonfinite raw sample rate stays in the immutable POD but JSON uses numeric zero with sample_rate_finite=false. Status performs the existing main-thread write only; no callback file/JSON writes are introduced.

Controls invoke the actual Bridge setup callback only with failed results or off-main metadata so native priming is not entered. They verify early completion, unchanged invalidation, exact successful offline and failed/nonfinite preimages, concurrent immutable slots, first-32 preservation/overflow, status JSON, and seeded near-wrap count saturation. Native admission and controller associations remain explicit test stubs; no DAW, plugin or device is loaded.
